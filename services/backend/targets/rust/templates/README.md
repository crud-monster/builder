# Rust server foundation

Generated by CRUD Monster Builder for the MongoDB Rust target.

```sh
cargo check
cargo test
```

Run the server with Rust 1.89 or newer:

```sh
DATABASE_URL=mongodb://127.0.0.1:27017/todo cargo run
curl http://127.0.0.1:3001/health
curl http://127.0.0.1:3001/graphql -H 'content-type: application/json' -d '{"query":"{ health }"}'
```

`DATABASE_URL` is required and must use `mongodb://` or `mongodb+srv://` with
an explicit database name. The driver validates the full URI. Startup pings MongoDB
before opening the HTTP listener and fails with a redacted error if unavailable.
One shared driver connection pool is used by the server and GraphQL context.

`/health` reports process liveness; `/ready` pings MongoDB and returns 503 when
unavailable. Set `HOST` (default 127.0.0.1) and `PORT` (default 3001) through the
environment. `.env.example` lists these settings; `.env` is not loaded automatically.

GraphQL exposes only `health: Boolean!`. CRUD, migrations, authentication and
authorization are pending. Requests are limited to 32 KiB, depth 8 and complexity
64. The server enables no cross-origin access. Ctrl-C shuts it down gracefully.

Models use `Record` and embedded entities use `Entity` as type-name suffixes.
Relations contain string IDs; entities are stored as typed nested values.
`Int` maps to `i32`, `Float` to `f64`, and `DateTime` to Chrono UTC timestamps.
Nullable fields use `Option`, including `Option<Vec<T>>` for nullable lists.
Schema field names are preserved in JSON through Serde renaming. Scalar
schema defaults are applied during deserialization. Virtual fields are not
persisted and are omitted from these record structs.

Hidden and underscore-prefixed fields, plus the built-in User password field,
are excluded from serialization. These records are not API request DTOs:
read-only attributes, validation patterns, uniqueness and permission rules are
not enforced by this scaffold. Do not expose record deserialization directly
as a write API. The original schema is kept under `src/generated/source.schema`.

The builder owns `src/generated/` and `.gmb-project.json`. Regeneration overwrites
its generated files while preserving your Cargo manifest, README, library,
main program, tests and Cargo lockfile. Use a new directory for a different
target or database provider. Commit `Cargo.lock` after your first Cargo build.
