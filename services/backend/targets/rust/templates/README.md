# Experimental Rust MongoDB CRUD

Generated by CRUD Monster Builder for the MongoDB Rust target.

```sh
cargo check
cargo test
```

Run the server with Rust 1.89 or newer:

```sh
DATABASE_URL=mongodb://127.0.0.1:27017/todo cargo run
curl http://127.0.0.1:3001/health
curl http://127.0.0.1:3001/graphql -H 'content-type: application/json' -d '{"query":"{ health }"}'
```

`DATABASE_URL` is required and must use `mongodb://` or `mongodb+srv://` with
an explicit database name. The driver validates the full URI. Startup pings MongoDB
before opening the HTTP listener and fails with a redacted error if unavailable.
One shared driver connection pool is used by the server and GraphQL context.

`/health` reports process liveness; `/ready` pings MongoDB and returns 503 when
unavailable. Set `HOST` (default 127.0.0.1) and `PORT` (default 3001) through the
environment or the project-root `.env`. Environment values override the file.

GraphQL exposes `health` and basic CRUD for supported scalar models. Only
explicitly public CRUD operations are enabled. Login/JWT authentication is
available; role/owner CRUD checks, relations and migrations are pending. Requests are limited to 32 KiB, depth 8 and complexity
64. The server enables no cross-origin access. Ctrl-C shuts it down gracefully.

Models use `Record` and embedded entities use `Entity` as type-name suffixes.
Relations contain string IDs; entities are stored as typed nested values.
`Int` maps to `i32`, `Float` to `f64`, and `DateTime` to Chrono UTC timestamps.
Nullable fields use `Option`, including `Option<Vec<T>>` for nullable lists.
Schema field names are preserved in JSON through Serde renaming. Scalar
schema defaults are applied during deserialization. Virtual fields are not
persisted and are omitted from these record structs.

Hidden and underscore-prefixed fields, plus the built-in User password field,
are excluded from serialization. These records are not API request DTOs:
deserializing a record alone does not enforce readonly fields, validation
patterns, uniqueness or permissions. The CRUD API uses separate DTOs. Do not
expose record deserialization directly as a write API. The original schema is kept under `src/generated/source.schema`.

The builder owns `src/generated/` and `.gmb-project.json`. Regeneration overwrites
its generated files while preserving your Cargo manifest, README, library,
main program, tests and Cargo lockfile. Use a new directory for a different
target or database provider. Commit `Cargo.lock` after your first Cargo build.

## GraphQL CRUD

For a Todo model with public permissions:

```graphql
mutation { todoCreate(input: {message: "Try Rust"}) { id message done } }
query { todoAll(limit: 20, offset: 0) { id message done } }
query { todoOne(id: "RETURNED_ID") { id message done } }
mutation { todoUpdate(id: "RETURNED_ID", input: {done: true}) { id done } }
mutation { todoRemove(id: "RETURNED_ID") }
```

Submit these operations separately to `/graphql`. One/Update return null for a
missing record; Remove returns false. Lists allow limit 1–100 and offset 0–10000.
Updates preserve omitted fields; null clears nullable fields. IDs, createdAt and
updatedAt are server managed. Hidden, readonly, system and relation fields cannot
be written. Lists and mutations returning records also require public One access.
All other access rules return Forbidden.

Models with custom relations, unique or regex constraints, required hidden or
readonly values, or defaults on hidden/readonly fields have no CRUD API yet.
System User/UserRole/File models are excluded. Collections use `gmb_rust_<Model>`;
IDs and dates are strings. This layout and API are separate from the full
TypeScript backend contract. CRUD driver errors are redacted and operations time
out after five seconds.

The editable server delegates to `generated::graphql::schema`. Regeneration
refreshes that schema and its permission checks while preserving server and
database helper edits. For older generated projects, merge the latest Cargo.toml,
server.rs and database modules from a fresh generated directory to enable CRUD.

## GraphiQL

```sh
DATABASE_URL=mongodb://127.0.0.1:27017/todo GRAPHIQL_ENABLED=true cargo run
```

Open <http://127.0.0.1:3001/graphql> to explore the schema and execute GraphQL
queries/mutations. The editor uses POST `/graphql` on the same server. Its
JavaScript/CSS loads from unpkg.com and requires browser internet access.

`GRAPHIQL_ENABLED` defaults to `false`; only `true` and `false` are accepted.
When disabled, GET `/graphql` returns 405 and POST still serves the API. This
flag does not grant additional access to data.

On existing generated applications, merge the new Cargo.toml features,
config.rs, server.rs, main.rs and .env.example from a fresh output directory.
They are preserved on regeneration. The new main uses
`server::router_with_graphiql(database, config.graphiql_enabled)`.

## Login and current user

`.env` contains a private random JWT signing key generated by the builder, is
excluded from Git and is preserved on regeneration. Do not publish it. The server
loads this file from its current working directory; process environment values
win. A missing/blank `JWT_TOKEN_SECRET` or one shorter than 32 bytes stops startup.

Create the first account locally, with MongoDB running:

```sh
DATABASE_URL=mongodb://127.0.0.1:27017/todo cargo run -- create-user you@example.test
```

The password is prompted twice without echo and must contain 12–72 UTF-8 bytes,
without NUL. There are no default accounts/passwords and no public registration.
Emails are lowercase ASCII with a unique database index. Passwords use bcrypt
cost 12; the CLI creates accounts with no roles.

```graphql
mutation Login($email: String!, $password: String!) {
  login(email: $email, password: $password) {
    token expiresIn user { id email roles }
  }
}
```

Put the returned token in the GraphiQL Headers panel:

```json
{"Authorization":"Bearer YOUR_TOKEN"}
```

```graphql
query { me { id email roles } }
```

Tokens last 15 minutes. Missing credentials yield anonymous `me: null`; invalid
Bearer headers/tokens return HTTP 401. Identity, current roles, disabled status
and tokenVersion are read from MongoDB for each authenticated request. No password
hash is exposed. Disabling/deleting an account or incrementing its tokenVersion
revokes access; rotating the signing key invalidates all tokens. Remove the token
from the client to log out. Refresh, registration, password change and recovery
endpoints are pending.

Login permits 10 attempts per email per 60 seconds, at most 1024 active email keys
and four concurrent operations per process. Use shared ingress limits for multiple
instances. Accounts live in `gmb_rust_User`; TypeScript storage is not migrated.
Authenticated callers still cannot bypass unimplemented owner/role/filter CRUD
rules. Those rules remain Forbidden.

On upgrade, merge Cargo.toml and auth.rs, lib.rs, config.rs, server.rs, main.rs
from a fresh generated project, and supply a random JWT_TOKEN_SECRET if your
preserved .env does not contain one. The new main initializes auth indexes and
uses `server::router_with_auth`.
